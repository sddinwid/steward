# ADR 0032: Bounded reserve-aware economic planning

Status: scientific source/container and independent reconciliation verified; governed Master/MCP/browser integration and deployed acceptance pending.

The existing isolated Python scientific service adds versioned `economic-allocation` and `economic-scenarios` capabilities in service 1.2.0. Existing 1.0.0/1.1.0 release mappings remain explicit. No new scientific service or financial executor is introduced. Economic inputs remain synthetic, closed and bounded to six source entities, eight programmes, twelve periods and eight noncash resources. The existing authenticated request scope includes every source, programme and resource-owning entity. The existing signed request, nonce replay protection, process isolation, memory/CPU/concurrency limits and total execution timeout continue to apply.

Source cash is original-currency integer minor units. Approved availability must reconcile exactly to gross observed cash less obligations, restricted balances, existing commitments, protected future requirements and reserves. A current shortfall is infeasible. One authoritative source pool per entity is allowed in a planning request; multiple programme assessments cannot be silently summed into that pool. Future generation is hypothetical period cash flow, never an increase to current approved availability. Already protected operating costs have an explicit bounded coverage vector so they are not deducted twice. Positive hypothetical net cash does not authorize any contribution.

The mixed-integer model selects indivisible conditional service units and proposed cash flows. Source cumulative balances cannot fall below protected requirements; receiving programme cash cannot go negative; budgets, required operating costs, minimum service units, maximum capacity and explicit source/recipient restrictions apply independently. Existing received programme money reduces new contribution requirements. Consumable resource capacity is limited across the whole horizon; reusable physical capacity is limited per period. Valuation never becomes a cash source. Staff/service operating costs must be included explicitly in source/programme assumptions.

Users specify a lexicographic service priority order. Each category's optimal total units is fixed before optimizing the next category; unlike service units are not added into a hidden weighted score. Programmes in the same category must declare comparable units. A final objective minimizes new contributions for those fixed service counts. Source restrictions and governance eligibility are inputs, not decisions made by the solver. Recommendations still require independent entity approvals, current reservations and receiving acceptance.

Each objective is capped at 0.5 seconds for standalone allocation and 0.15 seconds within scenario comparison, using one solver thread, fixed seed and zero relative gap. At most six objectives and five explicitly labelled scenarios are allowed. The existing overall process budget overrides these bounds. A solver timeout does not become a completed optimum. Exact Python integer checks validate every bound and constraint after each objective; independent TypeScript BigInt reconciliation checks source/receiver conservation, original currency, declared identity/restrictions, all costs/balances, noncash use and period effects before accepting a scientific result. This proves feasibility and financial reconciliation, not an independent proof of optimality.

30-day and 90-day horizons use explicit contiguous dates. Twelve-month horizons use twelve calendar intervals anchored to the original day, including month-end clamping and leap-year anniversaries. Conservative/baseline/expansion and bounded sensitivity scenarios scale explicitly documented hypothetical generation and costs only. Approved current cash, reserves, restrictions, commitments and physical capacity remain unchanged. Scenarios are not probabilities or statistical confidence claims. An unfunded unit cost is a conditional cost gap; capacity, budgets or restrictions can also prevent serving the unmet units. It is not a claim that additional cash alone solves every gap.

Outputs retain source effects, programme costs, conditional service capacity, noncash effects, priority order, assumptions, method, solver bounds and limitations. Internal proposed flows create zero additional ecosystem income. Missing costs or approved cash return insufficient data; infeasibility and incomplete optimization remain explicit. No participant-level data or authority is accepted, and no operational records are written.
