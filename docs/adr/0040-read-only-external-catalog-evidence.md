# ADR 0040: External catalogs are observed facts, not local classification or authority

Status: implemented for Phase 15E; operator/live acceptance pending.

The original closed external-observation v1 contract requires a known offering type and nonempty short code. The installed Shopify read transport does not establish a Steward offering type, and native names/SKUs can be absent or exceed local Catalog limits. A new additive `steward.external-catalog` 1.0.0 contract therefore provides provider-specific `catalog.shopify.read` and `catalog.printify.read` capabilities. The legacy contract remains supported.

Connections, product/variant discovery and exact lookup use the existing signed SSMA registry, approved bindings/workflows, durable outboxes and actual host receipts. They expose bounded pages of twenty normalized records. Later reads restrict the original provider installation/package, connection origin and semantic generation. No additional integration mechanism or commercial write transport is introduced.

New declared read namespaces `external_catalog_products_v1` and `external_catalog_variants_v1` identify normalized observations. Their revision is the provider's semantic synchronization generation, not the native cache row revision or an existing synchronization stream revision. Stable opaque record identities retain provider, connection and original remote product/variant identities. Cost-only changes and variant response order do not invent catalog fact changes. Stream, record and revision must all match.

Successful complete source reads persist immutable public connection origin and current synchronization provenance in the same transaction as cached products. No migration backfills a fresh lease from existing rows. Reads lock the synchronization state to keep pages coherent with that generation. Failure, missing profiles and lease expiry remain explicit. Shortening freshness takes effect immediately; relaxing it cannot extend the expiry captured at the last successful poll. Reading or replaying cached data never renews the observation time. Removed records remain retained with explicit removed status.

Native facts remain nullable and unchanged. Whitespace-only names/SKUs normalize to null in the projection while raw source records remain preserved; other nonblank values remain verbatim. A bounded projection that cannot represent a field reports unavailable without destroying the valid native cache. Import plans require explicit human local name/code/classification and appropriate type details. They preserve the original provider facts, mapping ownership, conflicts, history and exact-read evidence. They neither reprice accepted Sales nor grant stock, production or fulfillment permission.

A runtime audit found that Shopify's original global simulator prerequisite would prevent the new read-only capability in live mode. Its effective original constraints are moved onto every legacy provided and consumed capability. New reads have an independent `catalogReadEnabled` gate. Optional consumer `configuration` prerequisites are signed metadata supported only from platform 0.15.0; undeclared gates retain legacy disable behavior. Explicit independent gates do not override global prerequisites, disabled modules, permissions, binding approval, original-provider restrictions or domain rules. Pricing's explicitly empty provider gate denotes local read-only resolution independent of optional Catalog integration; Sales still requires its own governed flags and fresh writer authority.

The host and private module inbox enforce those gates. Paused source commands retain durable retry state. Governed executor deliveries attest the actual local source identity and include private capability identity for new platform-15 receivers; legacy receiver wire remains unchanged. No legacy simulator or commerce restriction is removed.

Synthetic transport and isolated PostgreSQL/browser results establish this implementation's behavior. They do not establish live Shopify/Printify compatibility, operator deployment or commercial production readiness. Separate live read-only and preservation gates remain required.
