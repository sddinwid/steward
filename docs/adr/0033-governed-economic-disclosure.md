# ADR 0033: Governed economic summaries and durable invalidation

Status: source modules, private outbox validation, signed Master exchange/API and presentation builds verified; deployed browser, scientific/MCP integration and full release acceptance pending.

Financial disclosure extends the existing named-account programme disclosure lease. The optional economic domain admits only `economic_summaries_v1`; it cannot be mixed with legacy mission aggregate or cash-state streams. The source Worker verifies the installed signed economic module, its current original operation/package identity, current enabled source administrator, programme management/publication permission and module-owned policy-scoped disclosure grant. The named Master account must explicitly accept the exact signed lease revision. A registry role alone cannot read financial summaries. Revocation and expiry deny current and historical evidence; immutable retained records are not erased. Existing mission disclosures and financial cash-state statements remain unchanged.

Each independently installed financial module creates a closed snapshot of its own authority. Source-side publication requires a separate, current reviewer quorum and a current delegated discloser; terms, policy and snapshot must still match at publication. Source cash summaries additionally revalidate the original availability assessment. Disclosure validity is bounded by source evidence freshness, policy expiry, relevant review expiry and the discloser's grant. Unknown noncash valuation remains unknown. No raw bank fields, participant records, documents, free-form case notes, passwords or connector credentials enter the closed projection. Financial summary publication grants no allocation, execution or payment authority.

Resource Availability summaries reconcile observed cash with disjoint protected requirements and holds. Budget summaries preserve approved plans, commitments, receipts, spending and encumbrances separately, by original currency and category. Coordination summaries preserve gross outgoing/incoming lifecycle amounts and unresolved states; internal movements create zero additional ecosystem income. These modules retain operational authority. Master stores analytical copies and never writes their databases.

The existing module capture/outbox and signed Worker synchronization carry both sealed summaries and `economic_summary_status_v1` invalidations. Append-only migrations install immutable invalidation evidence. Financial record mutations, resource holds, budget commitments/receipts/cancellations invalidate earlier programme summaries in the same transaction. Immutable summaries are not rewritten, and rollback also rolls back invalidation/outbox effects. The status stream contains only the original summary identity, source/programme scope, timestamp and a fixed reason. A late or duplicate summary cannot revive an invalidated snapshot, including when invalidation arrives first.

Before a Worker signs an outbox batch, the module host binds every envelope, source identity, nested economic contract, stream, version and declared provider kind to the verified package and trusted runtime identity. Master revalidates the complete closed envelope before inbox persistence. Stream identity is part of every evidence reference and database lookup, including status records that intentionally share the target summary UUID. Broad business-data access and ordinary finding workflows exclude both sensitive economic streams.

Master's scoped evidence reader resolves exact entity/installation/module/stream/record/revision references under the named account's live accepted disclosure. New calculations require the latest unexpired, uninvalidated source snapshot; older copies remain explicitly historical. Source availability is an as-of analytical snapshot within a declared freshness window, never a promise of legal distributability or real-time executable cash. A disconnected Worker cannot communicate a new invalidation immediately; the bounded disclosure/freshness window remains visible, and actual Worker reservation/execution always revalidates authoritative current state. No scientific result can bypass those local checks.

The shared source-disclosure interface discovers optional economic metadata alongside legacy programme modules. The operational financial forms/actions remain independently supplied signed module contributions to the existing renderer. Master adds a thin SSDS presentation of authorized resources, reserve/restriction protection, budget funding gaps, receipts, spending and reconciliation, without replacing module UI. Full source-to-service cost evidence, governed planning/MCP and end-to-end browser acceptance remain separate unfinished gates.
