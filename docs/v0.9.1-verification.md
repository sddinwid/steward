# Steward v0.9.1 — acceptance verification

All mandatory acceptance gates passed on 24 October 2026. Baseline v0.9.0 remains tagged at `66481a9fedf5047c38972fc481dbdad358b16916`. Work is on `ux/v0.9.1-business-intelligence`.

The distribution is `artifacts/releases/steward-0.9.1-mvp`, built from clean committed source `e8d4d5eaecf980146a53e6139cf559442f25480f`. Only this candidate is promoted after the evidence commit. Earlier 0.9.1 candidate directories are diagnostic snapshots, not the accepted delivery. `release.json.acceptanceEvidenceCommit` and the external `steward-0.9.1-acceptance.json` receipt identify final acceptance. The toolkit is an immutable source checkpoint; final acceptance documentation follows packaging to avoid a self-referential checksum.

## What changed

Master now presents evidence-derived opportunities, explicit human review, meaningful investigation titles and summaries, searchable/sortable/paginated history, structured finding details and acknowledgments, independent provider status, company performance and per-company/per-currency financial comparisons. Priority is explicit and tested: open review, severity, newest creation time, stable identity. Unknown confidence, urgency, impact and stakeholder assignment remain unknown.

Worker navigation still comes from verified, permission-filtered manifests. Categories collapse, retain browser/account state and support search. The shared renderer improves monetary inputs without changing integer-cent storage, dates, status labels, record references, consequential-action confirmation and table layout. There are no precompiled Inventory, Sales, Shopify or Printify screens in Worker core. Module routes, operations, authority and authorization remain intact.

New platform reads derive catalog summaries from existing results, enforce ownership/current scope and reuse the existing deterministic commerce calculator. There is no new database migration, event protocol, analytical execution engine or authentication subsystem. AI setup remains deployment-managed; the administration screen explains it and performs a bounded, credential-protected TLS reachability check. Reachability is not a claim of model readiness.

Regression testing exposed unnecessary root-package dependencies in commerce modules. Independently signed patches **Inventory 1.4.2, Sales 1.1.3 and Printify 1.0.6** remove them. Publication rejects direct core dependencies. Operational code and migrations are unchanged. Shopify remains 1.0.1; Procurement 1.0.2, Assets 1.0.3, Workforce 1.0.2, Operations 1.0.0 and Stock-ledger 1.0.0 remain available. Worker 2 initially had no Inventory; the Phase 5 regression later explicitly installed legacy Inventory 1.2.1 there. This was an isolated fixture installation, not a cross-Worker side effect.

Steward persisted `REPEATED_TOOL_CALL`, no result and no finding. Activity remains in History. Configuration was restored and the alias unloaded.

The explicit, schema-guided retry **`29969c3e-256f-40ea-abe5-f7fd2aec6188`** completed in **51,051 ms** with **5 actual model calls**:

1. `list_entities` — 2,130 ms model call.
2. `query_resource_matches` — 1,822 ms.
3. `query_business_relationships` — 4,450 ms.
4. `analyze_resource_sharing_by_id` — 12,909 ms.
5. Final evidence-supported response — 28,606 ms.

The model copied actual references: Assets `capacities` record `2d1888b2-a151-4df8-9888-4feda62dc236` revision 1 and Operations `storage_requirements` record `e6b02166-5e23-460d-a7ba-8cbbabe7bd97` revision 1. The retained observations show 800 m³ available, 500 m³ required, EUR 12,000 external monthly expense and EUR 3,000 total warehouse operating cost. Total operating cost was not substituted for assumed incremental cost.

With explicit assumptions of EUR 3,000 internal payment, EUR 1,000 incremental monthly cost, EUR 6,000 transition cost and 12 months, the deterministic service returned **EUR 11,000/month ecosystem benefit and EUR 126,000 over 12 months after transition**. The higher-cost sensitivity returned **EUR 10,000/month and EUR 108,000 over 12 months**. Consumer/provider effects and the zero-change baseline were independently recomputed. Full arguments, calls, calculations and source references are retained in `v0.9.1-acceptance-evidence.json` and the raw ignored artifact report.

The financial narrative matches those calculations and is accepted for **conditional opportunity review**, not business approval. The model uses generic “units” and mixes observed facts into its assumptions list. The source contract establishes cubic metres; Analyst and Finding details explicitly separate observed records, deterministic inputs/limitations and non-authoritative model wording. No guarantee of location suitability, cost avoidance or implementation is made.

The finding was launched and published through Chromium, delivered only to **Workers 2 and 3**, acknowledged through both Worker browsers and displayed back on Master. Worker 1 received no copy. Provider status reported a reachable real Ollama endpoint (`testModel: false`). Original model configuration and credential-file bytes were restored; no models remained loaded. ## Reproduction and recovery

Use the [release/presenter guide](v0.9.1-release.md) for portable install, upgrade, startup and shutdown. The exact payload was copied into `.steward/bi-mvp-toolkit`; `npm ci` and `npm run build` succeeded there without the checkout. Create the local output directory before optional development verification helpers:

```powershell
New-Item -ItemType Directory -Force artifacts | Out-Null
node scripts/release.mjs verify --bundle <distribution>
node scripts/verify-phase7-redeployment.mjs <synthetic-state> <distribution>
node scripts/smoke.mjs <synthetic-state>
```

Source-checkout acceptance commands used:

```powershell
npm run build
npm test
npm run test:smart:browser
node scripts/verify-phase8-regressions.mjs .steward/ux-release-acceptance
node scripts/verify-business-intelligence.mjs .steward/ux-release-acceptance
node scripts/verify-workspace-catalog.mjs .steward/ux-release-acceptance
node scripts/verify-workspace-currency.mjs .steward/ux-release-acceptance
```

The explicit real-model question and actual wire calls are retained in the investigation and raw report. The validation runner used `STEWARD_OLLAMA_BROWSER=1`, `STEWARD_VERIFY_PROVIDER_STATUS=1` and a report path; credentials came only from private files. Each suite that needs fixture credentials used the selected deployment's own `demo/presenter.json`. Deployment-mutating suites belong only on controlled synthetic installations.

Observed incidents were corrected and rerun:

- Windows reserved port ranges rejected initial 46000/50000-offset trials. Those incomplete services were stopped with volumes/private files retained; retries at offsets 16000/24000 passed. No networks or volumes were pruned.
- Lockfile generation with `npm install --prefix` from the root reintroduced the root package. Running from each module directory corrected it. Superseded diagnostic patches remain retained and are excluded from this distribution.
- Changed provider package identities rejected a legacy reservation. Explicit authorized binding/workflow re-approval restored new work; rejected attempts and original obligations were retained, not silently reassigned.
- Old text/capitalization assertions and unordered `compose images` comparisons failed despite unchanged image IDs. Assertions now check current presentation and keyed service IDs. Activation and advanced-field helpers wait for actual responses/attached controls. No security rate limit was weakened.
- The standalone optional redeployment helper passed preservation checks but could not write its report before an `artifacts` directory existed. Creating that output directory and rerunning produced a successful report and smoke result.
