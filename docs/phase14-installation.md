The Phase14 release is not yet accepted. The selected v0.13 operator deployment remains preserved. ## Additive API routing

After the secured mission routing layer is present, the economic routing provisioner creates an optional `economy` overlay. It adds `/api/v14/` without changing `/api/v2/`, `/api/v13/`, existing origins, credentials or module configuration. It creates no containers, volumes, financial records or policy. It requires an explicit existing deployment directory and never silently chooses a new development stack.

Build and test from the repository root:

```powershell
npm run build -w @steward/installer
npm test -w @steward/installer
node --test scripts/test-compose-operator.mjs
```

The routing-only provisioning command is:

```powershell
$deployment = (Get-Content .steward/operator/selection.json | ConvertFrom-Json).directory
npm run economy:provision -- "$deployment"
```

This command alone does not apply a deployment upgrade. API routing must be applied together with the verified Phase14 core release. Once the complete upgraded configuration has been reviewed by the release installer, the existing `select-deployment.mjs` and Compose helpers recognize `economy/compose.yaml` after mission routing and before image pinning. Ordinary operator commands remain `docker compose up -d`, `docker compose stop`, `docker compose ps` and `docker compose logs` using the same selected project and retained volumes. No second stack is required.

The provisioner records the original runtime identities and source routing hashes. Re-running preserves every generated byte. Identity changes, changed base routes, edited economic overlays, malformed identities and concurrent provisioning fail without overwriting the existing configuration. Review intentional configuration changes explicitly rather than deleting the installed overlay. Temporary staging cleanup is bounded to the newly generated directory.

## Analytical request bounds

Only the reviewed economic scenario route accepts up to 64 KiB. The core request cap remains 16 KiB, closed schemas retain all programme/source/vector limits, and the scientific and MCP execution budgets remain independent. The route exception supports bounded multi-programme forecast assumptions and does not raise general financial/module API request limits.
