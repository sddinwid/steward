## Checkpoint 13A — verified source foundations

This includes versioned synthetic service contracts, complete/complementary/correlated-stage aggregate suppression, safe resource allocation arithmetic, generic declarative form references, program/case access hooks, bounded provider profiles and signed peer proofs. Separate real PostgreSQL sealing/access harness **16 checks passed**; host outbox suite **11 passed**, peer crypto/actual pinned HTTPS **8 passed**, module-field presentation **8 passed**. The generic Master analytics/finding path now denies mission-specific data by default; programme-scoped Mission access is implemented in its later checkpoint, not granted by registry administration alone.

New private-module policies filter before pagination, derive program-qualified keys, recheck current grants before cached receipts, audit authorized and rejected reads outside rolled-back business transactions and normalize forbidden/missing records. Intake self-assignment is bound to a freshly created row in the same transaction; testing first exposed an old-record assignment gap, which was corrected and rerun. Original failure evidence is retained in the intake-gap-failed artifacts. Independent case revocation, program revocation, unassigned cases and forged identity all reject correctly. Audit failure after a committed mutation explicitly requires same-request reconciliation; it does not falsely claim rollback.

Only reviewed sealed fixed-cohort rows can be disclosed. Private membership ledgers reject repeated/overlapping cohorts, and changing a released vector is prohibited by database triggers. Small groups, small complements, derived occupancy/training use and correlated-stage differences suppress the entire linked vector including capacity/cost proxies. Funds require explicit authority and reconciled available/committed/transferred/spent amounts; duplicate allocation/transfer claims do not create additional money. These are bounded synthetic MVP safeguards, not differential privacy or legal/HMIS certification.

Signed program-service declarations restrict replication to closed aggregate/resource streams. Host outbox reads bind module, stream, columns, record identity and trusted enrolled source identity; unknown envelope/source fields, false source names, omitted privacy tags and arbitrary correlation text are rejected. Worker/Master closed-wire validation runs before inbox persistence. Worker MCP declarations for these modules must target the sealed aggregate operation. Existing signed legacy contracts retain their behavior.

Peer proof primitives verify enrolled identity, explicit independent TLS/publisher pins, bilateral reviewed grants, immutable provider/package identities, source/destination programs, purpose, replay and signed receipts. They are not yet integrated into running SSMA routing; remote binding/discovery/delivery acceptance remains a later cross-module gate. The existing entity-only resolver has not been weakened.
