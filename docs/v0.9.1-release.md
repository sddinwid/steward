# Steward 0.9.1 — installation and presentation

The v0.9.0 tag and distribution are preserved. Release acceptance is recorded in `v0.9.1-verification.md` and the exact-candidate gate manifest, not inferred from this guide.

## Installation and upgrade

Use Node 24, npm, Docker/Compose and OpenSSL. Run from the distributed `toolkit` directory; keep private state outside the distribution. Review bundle provenance before explicitly trusting its signed module packages.

```powershell
npm ci
npm run build
node scripts/release.mjs verify --bundle ..
$env:STEWARD_DEPLOYMENT = [IO.Path]::GetFullPath('../../steward-bi-state')
node scripts/release.mjs install --bundle .. --directory $env:STEWARD_DEPLOYMENT --project steward-bi-demo --port-offset 16000 --trust-bundled-modules --simulators
node scripts/release.mjs start --directory $env:STEWARD_DEPLOYMENT
node scripts/demo.mjs $env:STEWARD_DEPLOYMENT setup
node scripts/verify-phase8-commerce.mjs $env:STEWARD_DEPLOYMENT enroll
node scripts/smoke.mjs $env:STEWARD_DEPLOYMENT
```

On Windows, check `netsh interface ipv4 show excludedportrange protocol=tcp` and select an offset outside reserved ranges; this host rejected initial 46000/50000-offset trials without changing retained deployments. The verified retry uses offset 16000.

If Docker has exhausted its default subnet pools, choose an unused private prefix and run `node scripts/configure-network-pool.mjs $env:STEWARD_DEPLOYMENT 10.230` before repeating startup. Do not prune retained networks or volumes.

For this example offset, use `https://master.localhost:22100` and `https://worker-1.localhost:22201` (Workers 2/3: 22202/22203). Use the exact configured HTTPS origins; plain `localhost` is not an interchangeable sign-in hostname. The current synthetic acceptance environment uses Master 36100 and Workers 36201–36203.

Existing installations keep their own passwords, identities and private files. Fresh presenter credentials are written only to that deployment's `demo/presenter.json`; a different deployment is a different authentication realm. Never copy example passwords or overwrite an operator's credential files.

Back up private state and PostgreSQL databases before upgrading. From the new toolkit:

```powershell
node scripts/release.mjs upgrade --bundle .. --directory $env:STEWARD_DEPLOYMENT --trust-bundled-modules --simulators
node scripts/release.mjs start --directory $env:STEWARD_DEPLOYMENT
node scripts/release.mjs status --directory $env:STEWARD_DEPLOYMENT
node scripts/release.mjs stop --directory $env:STEWARD_DEPLOYMENT
```

No database reset or destructive rollback is needed. Repeating provisioning preserves existing configuration. To recover an interrupted start, repeat `start`; inspect retained diagnostics if it fails. Follow v0.9.0 recovery guidance for uncertain connector outcomes. Never re-submit an uncertain paid order.

## Presenter paths

Executive: sign in → Executive Overview → review an opportunity's affected businesses, original currency, estimated benefit and review status → open finding → review evidence, assumptions and recommended decisions → inspect delivery/acknowledgment → open originating investigation. History supports search, execution filtering, sorting and pagination. Companies distinguishes business entities from Master and exposes available source-backed performance. Reports keeps company/currency comparisons separate and labels the selected source range.

Business operator: sign in → find an authorized page or expand a business category → Orders/Inventory → create or edit permitted records using ordinary form controls → review fulfillment ownership and production/shipping costs → review local findings. Categories retain browser/account state. Integration screens label simulator/live mode. Consequential generated actions require confirmation, followed by the existing server authorization and idempotency controls. Canceling confirmation sends no action request.

Module screens remain generated from verified installed manifests. The core does not contain special Inventory/Sales/Shopify/Printify screens. Signed patch packages Inventory 1.4.2, Sales 1.1.3 and Printify 1.0.6 remove an unnecessary root-package dependency discovered during regressions. Historical releases remain unchanged; use these patches for current commerce installations. Module Manager upgrades preserve business records and require re-approval of affected governed bindings/workflows for new work. Completed obligations remain pinned to their original provider identity.

## AI availability and retained reports

Existing Intelligence, Run New Analysis and AI Configuration Status are separate. Reading historical reports requires no active LLM. Endpoint reachability is a bounded TLS probe, not proof that the selected model can complete an investigation. Test-model results remain explicitly labeled. Missing evidence, unknown costs, failed investigations and unavailable providers remain explicit.

Authorized Administration → AI Provider Configuration explains deployment-managed setup. `STEWARD_ANALYST_FILE` references the mounted private model configuration (deployment-relative `analyst/config/model.json`), including provider/model, approved HTTPS endpoint, CA and credential-file reference. Never enter secrets in business forms or commit them. Local Ollama still uses the existing authenticated TLS bridge. See the v0.9.0 installation guide for the real-model validation runner; it restores original private file bytes and unloads the temporary alias after testing.

## Verification commands

From a development checkout with a controlled synthetic deployment:

```powershell
npm run build
npm test
npm run test:smart:browser
node scripts/verify-business-intelligence.mjs $env:STEWARD_DEPLOYMENT
node scripts/verify-workspace-catalog.mjs $env:STEWARD_DEPLOYMENT
node scripts/verify-phase8-regressions.mjs $env:STEWARD_DEPLOYMENT
```

Deployment-mutating regressions belong only on synthetic fixtures. They deliberately exercise installations, outages, finding lifecycles and recovery. Financial source selection is bounded to the latest 20 approved observations per company/currency and is explicitly not an audited complete-period financial statement. No live paid commerce or production certification is claimed.
